# tcms-web decisions D-95 to D-100 (V&V metrics)

Copied verbatim from tcms-web DECISIONS.md at commit 739083b7 (branch dev). These records define the pass rate, verdict, delta, stability, failing-since and report rules that tcms-cli must reproduce.

**D-95 · Pass rate and verdict.** Pass rate = Passed / (Passed + Failed + Blocked). Executed = any status except Untested; Skipped counts as executed but is outside the pass rate. Gate passed when `passed*100 >= gate*denominator` (exact); the displayed percentage is rounded down so the badge never reads "90% · FAILED". Denominator 0 → `NO_DATA` (grey). An open run's verdict is `provisional: true` ("· in progress"). Verdicts are computed on read, never stored, so a gate change recolours history (decision-010).

**D-96 · Delta.** Exact pass rate of this run minus the previous run's, in percentage points, rounded to an integer; ↑ above 0, ↓ below, → at 0. No previous run or `NO_DATA` on either side: "—" with "first run" / "no data".

**D-97 · Stability.** Per case over the D-88 window: keep only Passed/Failed results oldest→newest (ignore Blocked, Skipped, Untested, absent); flips = changes between neighbours; Flaky if flips ≥ 4, else Failing if the last kept result is Failed, else Stable (includes no results). Flaky outranks Failing. 016.10 AC2 ("≤1 flip") is reworded to "otherwise Stable" at finalization. The Flaky KPI = Flaky cases in the selected run.

**D-98 · Failing since.** For a case Failed in the selected run, walk back through the plan's earlier runs: Failed extends the streak, Passed ends it, Blocked/Skipped/Untested/absent are skipped; result = the oldest run in the streak (number, id, createdAt).

**D-99 · Report endpoints.** `ReportController` under `/api/v1/workspaces/{ws}/reports`, read-only for any member: `GET /runs/{runId}/summary` → `RunReportResponse` {run (id, number, plan, status, origin, createdBy, createdAt, closedAt, tests/code branch+commit, CI pipeline id+url), gate {thresholdPercent, passRate|null, verdict, provisional}, counts {total, executed, passed, failed, blocked, skipped, untested}, previous {runId, number, passRate, delta}|null, flakyCount, suites[], problems[] (one row per Failed/Blocked case: runCaseId, caseId, title, suite, status, source, notes, defect (null until ORCH-023), failingSince, stability)}; `GET /history?planId&runId&limit=12` → {gate, runs[{id, number, createdAt, status, passRate, verdict}], rows[{key, caseId, title, suite, cells[status|null], flips, stability}]}; `GET /runs/{runId}/export.csv?layout=summary|heatmap`. Logic in pure unit-tested classes in `base/report/` (`PassRate`, `StabilityClassifier`, `FailingSince`, `SuiteBreakdown`). Suite = frozen `PlanRunCase.folder` (D-46); one row per folder prefix (so `payments` aggregates `payments/refunds`), `depth` for indenting, root shown "(root)", default sort by path, rows without a denominator show "—". The client derives the triage list (first 10 Failed), KPI filters and full failing list from `problems`.

**D-100 · Export without new dependencies.** CSV on the server with a StringBuilder (RFC 4180 quoting, UTF-8 with BOM): `summary` = one row per case (run_number, case_id, title, suite, status, source, result_date, run_pass_rate); `heatmap` = case_id, title, suite, stability, one `#N YYYY-MM-DD` column per run, final `PASS RATE` row. PDF = the browser's print to PDF with a `@media print` stylesheet (hides header/controls); while printing `document.title` = `plan-name_run-118_YYYY-MM-DD` (default file name). Playwright checks with `emulateMedia({media:'print'})` and a stubbed `window.print`. No npm/gradle input change (no CI image rebuild). Exports are read-only; CSV records audit `report.export` (runId, layout, format); PDF is not audited (no server request).
