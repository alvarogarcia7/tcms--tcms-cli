Facts verified while planning:
- The test-case schema is `schemas/tcms-schemas/tcms/test-case-main.schema.json`. The file `schemas/test-case.schema.json` does not exist. Read this schema before writing plans/ fixtures for the `type`, `schema`, requirement link field and the command and expected-output fields. Do not guess them.
- The test-run schema is `schemas/tcms-schemas/tcms/test-run.schema.json`; the YAML `schema:` value is `tcms/test-run.schema.json`.
- `test-executor generate <YAML>` writes a shell script; `test-executor execute <YAML>` generates and runs it. The log location of `execute` is not stated in `--help`; Task 3 measures it on one fake case and records it.
- The verifier folder mode is `verifier -f <PATH> -d <DIR> -F yaml -o <FILE> --run-id <ID> --build-id <ID> --tester <NAME> --environment <TEXT> --test-run <PATH> --success-on-completion`. `--test-run` writes the run record that trace-matrix and report read.
- `test-executor trace-matrix` fails when a requirement lacks a normal-range or robustness test case unless `--no-coverage-check` is passed. Scenarios full-one, half and none would fail without it, so the driver passes `--no-coverage-check`; gaps are shown by the gaps report instead.
- trace-matrix default `--id` is TM-<UTC time>, which is not deterministic. The driver always passes `--id`.
- Requirements input accepts an ID list, one `ID:HLR` or `ID:LLR` per line.
- Run records: `type: test_run`, `schema: tcms/test-run.schema.json`, `run_id`, `build_id`, `environment`, `tester`, `started_at`, `finished_at`, `results: [{test_case_id, verdict, verification_result_ref}]`. Fake values only.
- Decisions recorded for the SUMMARY (do not silently decide):
  - D-08-A: no stage of spec section 2 is replaced by replay. Generate, execute and verify run for real on fake test cases whose commands print fixed fake output.
  - D-08-B: the scenarios do not produce NOT RUN. NOT RUN stays covered by unit tests in testcase-reporting.
  - D-08-C: tcms-config/ is not part of the scenario folders (coordinator decision, matching the diagram). The baseline ID BL-FAKE-001 is a driver constant. Spec section 2 lists tcms-config/; this is a deliberate deviation.
  - D-08-D: run records are produced by verify into the output folder, so runs/ in each fixture holds only .gitkeep. Spec section 2 described runs/ as recorded inputs; this is a deliberate deviation and follows from running verify.
