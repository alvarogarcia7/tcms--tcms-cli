Facts verified while planning:
- `test-executor trace-matrix` fails when a requirement lacks a normal-range or robustness test case unless `--no-coverage-check` is passed. Scenarios full-one, half, none would fail without it, so the driver passes `--no-coverage-check` and the gaps are shown by the gaps report instead.
- trace-matrix default `--id` is TM-<UTC time>, which is not deterministic. The driver always passes `--id`.
- Requirements input accepts an ID list, one `ID:HLR` or `ID:LLR` per line.
- Run records: `type: test_run`, `schema: tcms/test-run.schema.json`, `run_id`, `build_id`, `environment`, `tester`, `started_at`, `finished_at`, `results: [{test_case_id, verdict, verification_result_ref}]`. Use fake values only.
- The test-case YAML field that links a test case to requirements must be read from schemas/test-case.schema.json before writing the plans/ fixtures. Do not guess it.
- The spec lists generate, execute and verify stages. Those need a live DUT. This plan replays the recorded run records in runs/ instead, and the driver writes a stage log that says so. This is a scope decision recorded in Open decisions below.

Open decisions (record in SUMMARY, do not silently decide):
- D-08-A: generate/execute/verify are replaced by replay of recorded runs/ records. If the user wants live execution in the scenarios, that is a new plan.
- D-08-B: the scenarios fixture NOT RUN (a linked test case with no result). The five specified scenarios do not produce NOT RUN; NOT RUN stays covered by unit tests in testcase-reporting.
</context>

Write run_scenario.sh. Bash 3.2 and BSD/GNU safe: no declare -A, no mapfile, no ${var,,}, no grep -P, no sed -r, no readlink -f, no date formats that differ between BSD and GNU (the driver never calls date; generated time comes from the argument).

Interface: SCENARIO comes from the environment or from --scenario NAME; --all runs the five in order; --generated-at TS defaults to 2026-11-01T12:00:00Z; OUT_ROOT defaults to test-acceptance/reports/scenarios. Reject an unknown scenario name with exit 1.

For the chosen scenario folder S, output folder O = OUT_ROOT/S (wiped first). Stages, in order, each logged with section and a stage log line in O/stage.log that records each stage as run or skipped:
1. validate: validate-yaml on S/plans/*.yaml and S/runs/*.yml (skip the stage cleanly when the glob is empty, and record it).
2. trace-matrix: test-executor trace-matrix S/plans --requirements S/requirements/requirements.txt --runs S/runs --id TM-FIXED-<S> --baseline-id BL-FAKE-001 -o O/matrix/trace_matrix.yaml --no-coverage-check. The baseline value is read from S/tcms-config/tcms.toml.
3. report: test-executor report --matrix O/matrix/trace_matrix.yaml --runs S/runs --kind traceability --format markdown --test-cases S/plans --generated-at <TS> -o O/reports/traceability.md. Then the same with --format asciidoc to O/reports/traceability.adoc. Do not generate PDF or HTML.
4. Stages generate, execute and verify are logged as "replayed from recorded runs/" (see context, decision D-08-A), not as run.

Binary resolution uses find-binary.sh; if a binary is missing, exit 1 with a message naming it. Any non-zero exit from a stage stops the run and exits 1. Exit 0 when all stages succeed, even when the report contains gaps (gaps are not failures here).

Do not write logs to /tmp; use O/ only.
