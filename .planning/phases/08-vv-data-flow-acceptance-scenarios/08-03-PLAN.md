Expected per scenario, clean run (from the fixtures in plan 08-02):
- full-two: REQ-001..REQ-004 VERIFIED, 0 NO TESTS
- full-one: REQ-001..REQ-004 VERIFIED, 0 NO TESTS
- all-but-one: REQ-001..REQ-003 VERIFIED, REQ-004 NO TESTS
- half: REQ-001 and REQ-002 VERIFIED, REQ-003 and REQ-004 NO TESTS
- none: REQ-001..REQ-004 NO TESTS
- All five clean: 0 FAILED, 0 ERRORED, 0 PARTIAL, 0 NOT RUN.

Expected per scenario, injected run (spec section 6): REQ-001 is FAILED in all five scenarios, because the injected case TC-INJ-001 is linked to REQ-001 and fails. The other requirements keep the clean-run values above. The spec says "FAILED, or the rule's equivalent such as PARTIAL". The rule in rollup.rs gives FAILED whenever any linked case fails, even if other cases pass, so the assertion requires FAILED exactly. PARTIAL would be a rule violation and must fail the check.

The injected case uses a command that prints a value different from its expected output, so the case really fails when executed. It is written only into a scratch copy under the scratchpad path (never into the committed fixture folders).
