# Phase 9 Plan 03: tcms-vv-report (TCMS-47.1) Summary

New workspace crate `tcms-vv-report` renders the metrics JSON of `tcms vv metrics` as a Markdown or AsciiDoc
report. It computes no figure, does not depend on the `tcms` crate, and labels the gate pass rate and the V&V
test-case pass rate separately.

## Deviations from the plan

- **Commit granularity:** one feat commit with tests and code, not separate RED and GREEN commits (CLAUDE.md: no
  failing tests committed; same as 09-02).
- **Cargo.lock:** the new member adds an entry to `Cargo.lock`. Committed with the crate; the plan did not list it.
- **Pipe fixture:** `tests/fixtures/pipe-and-newline.metrics.json` was made by `jq` from the SUT-1 metrics JSON: a
  schema error with a pipe and a line break, and one case ID with a pipe and a line break, marked FLAKY so that it
  appears in the stability table. It is not output of `tcms vv metrics`; it only tests escaping.
- **Strict nullable fields:** a nullable field (for example `gate.passRate`) must be present, with a value or `null`.
  The plan asked only for a missing `vvRun` to fail. Stricter by design, tested.
- **Commit and push:** the plan's Task 3 said to commit nothing; the user's instruction was to commit. Committed as
  above. Not pushed.
- **Zero-test-cases:** the plan's "each derived fixture" was read as the seven folders; one of them produces no
  metrics JSON (see AC 10).
- **Duplicated escape helper:** `escape` exists in both `markdown.rs` and `asciidoc.rs` (same code, different doc
  comments). Not refactored.

## Known issues

- The report shows `flakyCount` and per-case rows exactly as the JSON has them. In the escape fixture the count (0)
  does not match the one FLAKY row; this is expected for a hand-edited escape fixture and does not affect the
  real-output goldens.
- No output of the report is validated against a schema (none exists for the report; as in TCMS-47).
