<objective>
Add the report crate that renders the V&V metrics as a Markdown or AsciiDoc report (TCMS-47.1), from the
JSON that `tcms vv metrics` produces. The crate computes nothing and does not depend on the tcms crate.

Purpose: document pipelines need the gate verdict, pass rates and coverage as a readable report. Because
the report reads the JSON, its figures are the CLI's figures (TCMS-47 goal: the same numbers everywhere).
Output: new workspace crate `tcms-vv-report`, golden reports, docs, DATA_FLOW section 4.5 update.

Depends on 09-02 because the report shows the window and parameter sources that 09-02 adds.
Test-first: Task 1 writes the golden and exit-code tests; Task 2 implements; Task 3 writes docs and generates goldens.
</objective>

```
stability{flakyThreshold,flakyCount,cases[{caseId,stability,flips}]}
loadSummary{distinctCases,schemaErrorCount,schemaErrors[{file,error}],runsRecorded}
parameters{...}   // from 09-02
```

input.rs: deserialize the metrics JSON into typed structs with serde (camelCase, Option for nullable fields). Missing
documented field: return InputError naming the field path (for example "vvRun"). No arithmetic is done here.

Sections, in this fixed order, in both formats:
1. Header: run id, startedAt, finishedAt (or "in progress"), provisional, generatedAt, gate threshold.
2. Gate verdict: passRate display and exact, counts, denominator, verdict, deltaFromPrevious, previousRunId.
   Null passRate: "NO_DATA" with no percent sign. Null delta: "n/a".
3. V&V run figures: vvPassRate under the label "V&V test-case pass rate", passed and total test cases, step coverage
   with passed and total steps. Null: "n/a".
4. Requirement coverage: summary counts, then one row per item (id, coverage, executed of total, problem reports,
   open problem reports).
5. Stability: flaky threshold, flaky count, window (from `parameters` when present; "not recorded" otherwise), and the
   cases whose stability is FLAKY or FAILING.
6. Load summary: distinct cases, runs recorded, schema error count, and the listed schema errors (file and error).

Escaping: in Markdown and AsciiDoc tables, replace "|" with "\|" and newline characters with a space inside every cell
built from an ID or error message.

Exit codes in main.rs: 0 success (also FAILED and NO_DATA without the flag); 1 for any error; 2 only when
--fail-on-gate and verdict is FAILED, after the report is written. The verdict text comes from the input, not computed.

Byte-identical output: no timestamps other than generatedAt from the input; stable ordering of the input arrays as given.
