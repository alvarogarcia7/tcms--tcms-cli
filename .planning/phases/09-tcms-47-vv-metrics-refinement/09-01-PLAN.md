<objective>
Add the producer side of the V&V data set (TCMS-47.3): combine the per-case test results of one run into
the single run record that `tcms vv metrics` already reads.

Purpose: `tcms vv metrics` reads one `runs/<RUN_ID>/test-run.yaml`. Today the 63 per-case results are
separate files, so the CLI cannot see a run as a whole. This plan closes that gap without changing the
metrics code.
Output: `tcms vv combine` subcommand, combinator module, binary tests on a 63-file layout, docs.

Test-first: Task 1 writes the failing tests, Task 2 implements, Task 3 wires the CLI and the docs.
</objective>

- runs/<RUN_ID>/test-run.yaml: run_id, plan_id (optional), started_at, finished_at (optional),

- runs/<RUN_ID>/verification-results.yaml: test_results: [{test_case_id, total_steps, passed_steps}]

Verdict vocabulary read by vvmetrics::Status::from_verdict: pass, fail, error, blocked, skipped,
not_executed, untested.

schemas_root, source_name).

Create crates/tcms/src/vvcombine.rs. Public entry: `pub fn combine(root: &Path, run_id: &str, schemas_root: &str, now_rfc3339: &str) -> anyhow::Result<CombinedRun>` where CombinedRun holds the two rendered YAML strings and counts. Behaviour:
- Read the per-case test_result files of the run (locate them with the layout read in the script; the run
  folder is runs/<RUN_ID>/ and the per-case files are the ones the script produces for that run).
- run_id and plan_id come from the shared run metadata; started_at and finished_at are the earliest and
  latest case timestamps (the script's execution-log timestamps). If no finish timestamp exists, finished_at
  is omitted so the run is provisional.
- Verdict mapping: overall_pass true gives `pass`, false gives `fail`, a case with no result for the run gives
  `not_executed`. A case with no per-case file at all is not invented as a result; only the documented
  missing-run marker in the per-case input produces `not_executed`.
- Duplicates: for one test_case_id, the entry with the latest started_at wins. A `not_executed` entry never
  replaces an executed (`pass` or `fail`) entry, even when it is newer.
- Output one results entry per test_case_id, sorted by test_case_id, and one test_results entry per
  test_case_id in verification-results.yaml with total_steps and passed_steps from the per-case data.
- Validate both rendered documents with testcase_common::parse_and_validate_yaml_string against the test-run
  schema for test-run.yaml. For verification-results.yaml there is no schema in the repository (CONTEXT Q3):
  check the fields that vvcmd::load_steps reads and return an error naming the missing field.
- Return an error before anything is written when validation fails. Writing is done by the caller.

Add `mod vvcombine;` to crates/tcms/src/main.rs. Keep the module free of clap types.
