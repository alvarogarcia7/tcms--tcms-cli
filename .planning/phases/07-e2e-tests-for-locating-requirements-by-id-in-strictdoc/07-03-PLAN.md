Fixture facts (from plan 07-02, content fixed by the real export):
- locate/export.json: SYS-1 level system, status approved, title "Remote profile management";
  HLR-1 level HLR, status approved, title "Update profile metadata"; LLR-1 level LLR, status in_review,
  title "Parse the update frame". Nothing else is in the export.
- refused-level/export.json: one item HLR-8 with LEVEL chapter.
- no-level/export.json: one item HLR-9 with no LEVEL.

Config used by every test (copy of the STRICTDOC_YAML in requirements_cli.rs plus LLR in document_map):
product_id PROD-002, requirement_source strictdoc, one system: name strictdoc, type strictdoc_html,
base_url https://pages.example.com/srs, id_pattern '^(SYS|HLR|LLR)-[0-9.]+$', url_template
'{base_url}/{doc}.html#{id}', document_map SYS: system-requirements, HLR: software-requirements,
LLR: low-level-requirements. Expected URLs therefore are
https://pages.example.com/srs/system-requirements.html#SYS-1,
https://pages.example.com/srs/software-requirements.html#HLR-1,
https://pages.example.com/srs/low-level-requirements.html#LLR-1.

Output contract of locate (Phase 6 plan 06-02; the tests assert these strings exactly):
- found: `HLR-1: found in strictdoc (strictdoc) at level HLR "Update profile metadata" [approved] <url>`
- not found: `HLR-99: not found in strictdoc (strictdoc)`
- text format: each line prefixed `✓ ` or `✗ `, final stdout line `N of M requirement IDs found`;
  plaintext: bare lines only; json: pretty array of objects with keys id, found, source, system, level,
  title, status, url.
- exit 1 additionally prints `not found: N of M requirement IDs` on stderr; exit 2 prints `error: ...`
  on stderr and nothing on stdout.
- a repeated ID is reported once, at its first position; results are in command-line order.
If locate.rs prints something different from this contract, do not edit the expectation to match: stop
and report the difference, because it is a Phase 6 deviation.
