Requirement references (this phase has no REQUIREMENTS.md IDs of its own; IDs are those of Phase 6):
LOOK-03 (a StrictDoc ID is found in the local export, line shows the level) and LOOK-04 (exit 0/1/2;

Decision of this plan on the old layout (DECISIONS.md Q3 "Open (assumption)"): the old lowercase layout
is DROPPED, as DECISIONS.md recommends. Nothing real produces it. Keeping a second reader would keep
the wrong shape alive in docs and tests. A file in the old layout is refused with a message that names
DOCUMENTS.

Exit codes: `locate` exits 2 on a refused export (Phase 6 D-06). `import` and `trace-matrix` keep their
existing error exit (1); this plan does not change any exit code, only which files are accepted.

Real layout facts (verified in DECISIONS.md Q1 against StrictDoc 0.20.0 and 0.30.4):
- top level: DOCUMENTS (array) and _COMMENT; each document: TITLE, GRAMMAR (ignore), NODES, _NODE_TYPE.
- node _NODE_TYPE is DOCUMENT, SECTION, TEXT or REQUIREMENT; SECTION nodes hold NODES (nested to any depth).
- REQUIREMENT node keys seen: UID, LEVEL, STATUS, TITLE, STATEMENT, RELATIONS, COMMENT, _TOC. UID, LEVEL, STATUS, TITLE and STATEMENT are all optional in StrictDoc's default grammar.
- RELATIONS entry: TYPE (for example Parent) and VALUE (the other UID).
- the export holds no file path anywhere.

Interfaces that must NOT change (06-01 and Phase 6 plans call them):
- pub fn parse_export(json: &str, commit: &str) -> Result<Vec<RequirementRecord>>
- pub fn export_levels(json: &str) -> Result<Vec<(String, String)>>
- pub struct ExportItem { pub uid: String, pub level: String, pub title: Option<String>, pub status: Option<String>, pub path: String }
- pub fn export_items(json: &str) -> Result<Vec<ExportItem>>
- private: struct Export { documents: Vec<Document> }, Document { path: String, requirements: Vec<Item> }, Item { uid, level, title, statement, status, parent_uids, safety_related, security_related } and fn check_item(path, item) stay as the internal model; the new code builds them from the real layout.

Phase 6 test files this plan touches exist only after Phase 6 is executed (external_depends_on). If
