    escape_adoc table (input -> exact output; a character reference is the decimal form `&#NN;`):
    - plain text such as `HLR-1` and `Some title 2026` -> unchanged
    - `a|b` -> `a&#124;b`
    - `line1\nline2`, `line1\r\nline2`, and a tab -> each line break or control character becomes one space (`line1 line2` for the first two, which means `\r\n` gives one space)
    - `*bold*` -> `&#42;bold&#42;`; `_it_` -> `&#95;it&#95;`; a backtick pair -> `&#96;`; `#mark#` -> `&#35;mark&#35;`; `+++raw+++` -> `&#43;&#43;&#43;raw&#43;&#43;&#43;`; `^sup^` and `~sub~` -> `&#94;` and `&#126;`
    - `[[anchor]]` -> `&#91;&#91;anchor&#93;&#93;`; `<<xref>>` -> `&#60;&#60;xref&#62;&#62;`; `{attr}` -> `&#123;attr&#125;`
    - a backslash -> `&#92;`; an ampersand -> `&#38;` (so the text `&amp;` renders literally as `&amp;`)
    - `http://x.y` -> `http&#58;//x.y` (a colon followed by a slash is encoded so no bare URL is auto-linked); a colon not followed by a slash stays `:` (so `09:00:00Z` is unchanged); `a@b.c` -> `a&#64;b.c`
    - `include::/etc/passwd[]` -> no `include::` substring remains (the colon is followed by a slash, and the bracket is encoded)
    - empty string -> empty string
    - Idempotence is NOT required (the function is applied once per value).

    Layout properties, asserted with assert_eq on a full literal in a golden test over the same fixture as the Phase 2 Markdown golden test (matrix TM-1, baseline None, runs RUN-1 and RUN-2, builds b1 and b2, one environment, tester alice, generated_at 2026-10-31T09:00:00Z, obsolete_excluded Some(2), document docs/srs.sdoc with HLR-1 VERIFIED and LLR-2 FAILED, empty document docs/empty.sdoc):

    - One `== Document: <escaped name>` heading per section, `not recorded` for a None name, in model order
    - A section without rows has the line `No traceable content` and no table
    - Requirement table has the eight Markdown columns in the Markdown order and a header row; coverage cells yes or no; status cell is the status label
    - Cases of one cell are separated by a hard line break (a space and a plus at the end of the line, then a new line); an empty cell is `-`; a case without a run reads `<id> (NOT RUN, no result)`
    - The text ends with exactly one newline

  <action>
    Create `render_asciidoc.rs` and add `pub mod render_asciidoc;` to lib.rs, leaving every other module declaration untouched. Write the escape table test and the golden test first (commit as test), then the implementation (commit as feat).

    Public items: `pub fn escape_adoc(text: &str) -> String` and `pub fn render_asciidoc(model: &ReportModel) -> String`.

    Escaping design (D-02, D-06). AsciiDoc has no single backslash escape that works for every construct, so use numeric character references: Asciidoctor passes `&#NN;` through unchanged and shows the character, and the reference text contains none of the characters that start markup, so it can never be interpreted. escape_adoc walks the characters of the input once. Line feed, carriage return, tab and every other control character become one space; the pair carriage return plus line feed becomes one space. These characters become `&#<decimal code>;`: ampersand, less-than, greater-than, asterisk, underscore, backtick, hash, plus, caret, tilde, left and right square bracket, left and right curly brace, backslash, pipe, and the at sign. A colon becomes `&#58;` only when the next character is a slash. Everything else is copied. Pipe is encoded as a reference, not as a backslash pipe, so no table separator can survive inside a value, whatever the AsciiDoc version. Apply escape_adoc to EVERY string that comes from the model and is written into the document: matrix id, baseline, run ids, build ids, environments, testers, generated_at, document names, requirement ids, level text, test case ids, run ids in cells. Status, outcome and column labels and the fixed words are written as literals and are not escaped. Never build output with unescaped model strings.

    Layout. Build the string with explicit push_str and format calls in a fixed order, like render_markdown. Use these constructs: the title line with a single equals sign; section lines with two equals signs; tables written as an attribute line, a line of pipe and three equals signs, one cell per line starting with a pipe, and a closing line of pipe and three equals signs. Use the attribute `cols` with relative widths and `options="header"` for the header row (exact widths are at the executor's discretion). Each cell is written on its own line as a pipe followed by the escaped value; a cell with several cases uses the hard line break described above so that every continuation line contains no pipe at all. Mirror Markdown section for section, including an Inputs section if the executed model has one. Do not read files, the clock, the environment, or HashMap/HashSet iteration (D-05). Do not add dependencies.
