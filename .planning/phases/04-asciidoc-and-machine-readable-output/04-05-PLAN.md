<objective>
Close the 04-VERIFICATION gap for tcms-43.4 acceptance criterion 5: the traceability report in both shapes (A and B) must be schema-validated before it is written. Today the shapes exist only as Markdown (`render_shape_a`, `render_shape_b`), the `--shape a|b` flag is rejected for every format except Markdown, and no shape output passes `validate_document`.

Decision D-04-6 (in .planning/DECISIONS.md) fixes the approach: validate shape A and shape B documents before write. This plan implements that decision in three layers: the local report schema describes both shapes, the library builds shape documents from the same ReportModel and validates them, and the CLI validates them before any write for every format.

Purpose: OUT-02 says every machine-readable output is validated against a local schema before write. A shape is a traceability report, so it falls under the same rule. OUT-01 (AsciiDoc) is also touched because the AsciiDoc branch currently ignores `--shape`; dropping the guard without wiring it would silently emit the grid.

Output: an extended report schema, `build_shape_document` and `check_document` in the library, shape-aware wiring in `report()`, and a new E2E test file. The grid document and default Markdown output are unchanged.

Dependencies: depends_on 04-04 (complete). Wave 1 as assigned by the gap-closure orchestrator; no other plan in this gap set shares files with this one.
</objective>
