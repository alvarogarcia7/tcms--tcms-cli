<objective>
Create the local JSON report schema with the `type` and `schema` envelope and a `kind` field (D-03), the serialisable `ReportDocument` for all four report kinds, built from the Phase 2 `ReportModel` (traceability) and the Phase 3 views (summary, gaps, problems), and the pure validation function (D-04 building block). OUT-02 is covered for all four kinds.

Purpose: JSON and YAML output (plan 04-03) is a serialisation of one typed document per kind that has been checked against a schema that is versioned in the repository.
Output: schema file, envelope enum entry, `report_document.rs`, schema tests for all four kinds.

SCOPE: all four kinds are in this plan. Each kind has one content shape in the schema: `traceability_content` (Phase 2 document rows), `summary_content` (Phase 3 run and requirement rows and linked counts), `gaps_content` (the four Phase 3 gap lists) and `problems_content` (Phase 3 problem rows and missing count). The schema is version v1 and is closed per kind.

PREREQUISITES: Phase 2 plan 02-02 (`model.rs`) and Phase 3 (summary, gaps, problems, view) are executed and verified. The executor reads the real files first and records any name difference in the SUMMARY.

<interfaces>
Schema conventions in this repository (read, do not change):
- Local versioned schemas live in `schemas/tcms/*.schema.v1.json`, Draft-07, with `type` and `schema` as required `const` properties (see test-results-container.schema.v1.json). The URI `tcms/<name>.schema.v1.json` resolves to `<schemas root>/tcms/<name>.schema.v1.json` in `testcase_common::envelope::resolve_schema_uri`.
- `schemas/tcms-envelope.schema.json` lists the allowed `type` values in an enum and requires the schema URI to match `^tcms/.*\.schema(\.v\d+)?\.json$`.
- `schemas/tcms-schemas/` is the vendored shared set: read only, must stay byte-identical.
- `scripts/validate_envelope_schemas.sh` (make validate-envelope-schemas) scans `schemas/tcms/` and has a case table of known schema files.
- jsonschema is a workspace dependency (`jsonschema = "0.17"`); `testcase-common/src/yaml_loader.rs` shows how a Draft-07 schema is compiled and errors are listed.

Phase 2 (model.rs, executed): Header fields matrix_id, baseline_id (Option), run_ids, build_ids, environments, testers (Vec), generated_at, obsolete_excluded (Option<usize>); DocumentSection name (Option) and rows; RequirementRow requirement_id, level (HLR or LLR), status, normal_range_covered, robustness_covered, cases; CaseEntry test_case_id, column (normal_range, robustness, other), outcome (pass, fail, error, NOT RUN), run_id (Option).

Phase 3 (executed), the types the summary, gaps and problems documents are built from:
- view.rs: `ViewInput { model: &ReportModel, selection: &RunSelection }`; `ResultCounts { pass, fail, not_executed, error, total }` (all usize).
- summary.rs: `SummaryReport { header: Header, runs: Vec<RunSummaryRow>, requirements: Vec<RequirementSummaryRow>, linked: ResultCounts }`; `RunSummaryRow { run_id, build_id, used: bool, excluded_reason: Option<String>, counts: ResultCounts }`; `RequirementSummaryRow { requirement_id, level: RequirementLevel, status: VerificationStatus, counts: ResultCounts }`; `pub fn build_summary(input: ViewInput) -> SummaryReport`.
- gaps.rs: `GapsReport { header: Header, no_tests: Vec<GapRequirement>, missing_normal_range: Vec<GapRequirement>, missing_robustness: Vec<GapRequirement>, no_result: Vec<GapCase> }`; `GapRequirement { requirement_id, level: RequirementLevel, document: Option<String> }`; `GapCase { test_case_id, requirement_ids: Vec<String> }`; `pub fn build_gaps(input: ViewInput) -> GapsReport`.
- problems.rs: `ProblemsReport { header: Header, rows: Vec<ProblemRow>, missing_count: usize }`; `ProblemRow { test_case_id, verdict: Verdict, run_id, build_id, problem_report_id: Option<String>, requirement_ids: Vec<String> }`; `pub fn build_problems(input: ViewInput) -> ProblemsReport`. Only Verdict::Fail and Verdict::Error reach a row (Verdict is in testcase-verification/src/test_run.rs).
- Status labels: VerificationStatus::label() (VERIFIED, FAILED, ERRORED, NOT RUN, PARTIAL, NO TESTS). CaseOutcome::label() (pass, fail, error, NOT RUN). TestColumn::label() (normal_range, robustness, other).

Environment: run cargo with CARGO_HOME=$HOME/.cargo-user.
