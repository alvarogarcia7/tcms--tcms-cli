<objective>
Wire AsciiDoc, JSON and YAML output for all four report kinds into `test-executor report` with `--format` (D-01), validation before write with exit 1 on failure (D-04), and prove it from the command line, including hostile strings (D-06) and determinism (D-05). Markdown output stays byte-identical to commit 5862408.

Purpose: Phase 4 success criteria 1 to 3 become something a user can run for every report kind. OUT-01 and OUT-02 are addressed here and are closed in REQUIREMENTS.md only after this plan's verification passes.
Output: `--format` on `report`, the library entry points that render a list of documents, a multi-kind AsciiDoc join, CLI tests, documentation.

SCOPE: all four kinds in all three new formats. The `--shape a|b` layouts (Phase 2 D-02-6-2) are Markdown-only in the CLI for this plan; asciidoc, json and yaml reject them with a usage error (exit 2, the same mechanism that `--shape` already uses). Rendering shapes in AsciiDoc is a follow-up; the library functions from 04-01 exist but are not wired here. The exit code scheme of Phase 5 (exit 2 as a general usage code, `--fail-on-gaps`) is not changed; this plan only reuses the exit 2 that `--shape` already returns.

PREREQUISITES (all executed, verified against the code before this revision): Phase 2 plan 02-04 (`--generated-at`, `--test-cases`, `--requirements-export`, `fn report`), plan 02-06 (`--shape`, `ReportShape`, usage check before any input is read), Phase 3 plan 03-05 (summary, gaps and problems views and `build_summary`, `build_gaps`, `build_problems`), plans 04-01 (AsciiDoc renderers), 04-02 (`report.schema.v1.json` for all four kinds, `ReportDocument`, `build_document`, `build_summary_document`, `build_gaps_document`, `build_problems_document`, `validate_document`) and 04-03 (`render_json`, `render_yaml`, `OutputError`, which take the traceability model only and stay unchanged).

Note on the current code: `report` has no `--format` option yet. The `format: String` field at main.rs line ~231 belongs to `regression-select`; do not reuse or change it.

- `render_data::render_documents_json(&[ReportDocument], &Value) -> Result<String, OutputError>`: one document gives the object text of render_json; more than one gives a pretty JSON array of the documents in the given order; every document is validated before any text is produced.
- `render_data::render_documents_yaml(&[ReportDocument], &Value) -> Result<String, OutputError>`: one document gives the text of render_yaml; more than one gives the texts joined with `---\n` lines; each text is parsed back and validated before return.
- `render_asciidoc::join_asciidoc_documents(&[String]) -> String`: the first part unchanged; every later part has each line that starts with `=` given one more `=` (a level-0 title becomes level 1, a level-1 heading becomes level 2); parts are joined by one blank line; one trailing newline. Safe because escaping (04-01, D-06) guarantees that no model value starts a line with `=`.
