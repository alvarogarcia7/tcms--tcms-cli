<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| command line -> file system | `--output` creates or truncates a user-chosen path |
| user data -> machine-readable document | CI tools parse and act on the output |
| schemas/ directory -> validator | The schema file is read at run time from the working directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Tampering | `--output` file | mitigate | The file is created only after rendering and validation succeeded; a CLI test asserts the file does not exist after a validation failure |
| T-04-11 | Repudiation | exit status on bad output | mitigate | Validation failure exits 1 with the violated paths on stderr; a test asserts the exit code and message |
| T-04-12 | Tampering | missing or altered schema in schemas/ | mitigate | A missing or unreadable schema is an error naming the path and writes nothing; test for the missing schema; a schema that does not compile gives a `does not compile` error (library test) |
| T-04-13 | Tampering | stdout mixed with diagnostics | mitigate | New formats print only the document on stdout; summary and notes go to stderr; tests parse stdout as JSON, YAML and AsciiDoc |
| T-04-14 | Information disclosure | document content | accept | The report holds the same project data as the inputs; no new data source |
| T-04-SC | Tampering | package installs | accept | At most serde_json as a workspace dependency of test-executor (already in the workspace); no new package |
</threat_model>
