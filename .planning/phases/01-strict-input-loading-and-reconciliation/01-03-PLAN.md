```rust
#[derive(Debug, Clone, PartialEq, Eq)] pub struct SelectedResult { pub test_case_id: String, pub verdict: Verdict, pub run_id: String, pub build_id: String, pub started_at: String, pub problem_report_id: Option<String>, pub verification_result_ref: Option<String> }
#[derive(Debug, Clone, PartialEq, Eq)] pub enum RunUse { Used, Excluded(String) }
#[derive(Debug, Clone, PartialEq, Eq)] pub struct RunReport { pub run_id: String, pub build_id: String, pub started_at: String, pub path: PathBuf, pub total: usize, pub decided: usize, pub superseded: usize, pub not_executed: usize, pub use_: RunUse }
#[derive(Debug, Clone, Default)] pub struct RunSelection { pub results: BTreeMap<String, SelectedResult>, pub runs: Vec<RunReport>, pub builds: BTreeSet<String>, pub notes: Vec<String> }
impl RunSelection { pub fn used(&self) -> impl Iterator<Item = &RunReport>; pub fn excluded(&self) -> impl Iterator<Item = &RunReport>; }
impl std::fmt::Display for RunSelection { /* layout below */ }
pub fn select_results(runs: &[LoadedRun]) -> RunSelection;
```

Excluded reasons (exact strings): total == 0 -> "no results"; decided == 0 and superseded == 0 -> "only not_executed results"; decided == 0 otherwise -> "every executed result superseded by a later run".

RunSelection Display layout (exact; runs listed in selection order = started ascending then run_id):
```
Run selection (per test case, the latest run with an executed result decides)
  Builds used: b1, b2
  Runs used: 1
    RUN-2  build b2  started 2026-10-28T11:00:00Z  decided 1, superseded 0, not_executed 0
  Runs excluded: 2
    RUN-1  build b1  started 2026-10-28T10:00:00Z: every executed result superseded by a later run
    RUN-3  build b3  started 2026-10-28T12:00:00Z: only not_executed results
  Selected results: 1
    T1  fail  RUN-2
  Notes: none
```
Empty builds render "  Builds used: none"; notes render as "  Notes:" then "    - {note}" lines. `started` shows the record's original started_at string.

<feature>
  <name>Run selection: latest executed result per test case decides</name>
  <files>crates/testcase-reporting/src/select.rs</files>
  <behavior>
    Table-driven tests (one `cases` table of (name, runs as (run_id, build, started_at, results), expected verdict and run_id per test case)) plus targeted tests:
    - demo (CONTEXT specifics): T1 pass in RUN-1 at 10:00Z, fail in RUN-2 at 11:00Z, not_executed in RUN-3 at 12:00Z -> T1 = fail from RUN-2; RUN-3 Excluded("only not_executed results"); RUN-1 Excluded("every executed result superseded by a later run"); RUN-2 Used with decided 1
    - pass after fail -> pass from the later run (D-02)
    - pass after error -> pass from the later run (D-02)
    - error after pass -> error from the later run (D-02)
    - fail after error -> fail from the later run
    - later run omits T1 but has T2 -> T1 keeps the earlier result, T2 from the later run (D-03)
    - run with no results -> Excluded("no results")
    - test case with only not_executed results anywhere -> absent from `results` (it has no executed result)
    - input slice in reverse order gives an identical RunSelection (order independence)
    - started_at "2026-10-28T12:30:00+02:00" (= 10:30Z) is earlier than "2026-10-28T11:00:00Z": the 11:00Z run wins (instant comparison, D-01)
    - equal started_at for RUN-A (pass) and RUN-B (fail) on T1 -> fail from RUN-B, and notes contain "T1: runs RUN-A and RUN-B share started_at 2026-10-28T10:00:00Z; RUN-B wins by run_id order" (D-16)
    - RUN-1 build b1 decides T1, RUN-2 build b2 decides T2, RUN-3 build b3 only not_executed -> builds == {b1, b2} (D-04: no build filter, only used runs' builds)
    - a used run that also has a superseded and a not_executed result reports decided 1, superseded 1, not_executed 1 and stays Used (D-05)
    - Display of the demo selection equals the exact layout in the interfaces block (assert_eq on the full string)
  </behavior>
  <implementation>
    Per D-01/D-16: copy references into a Vec, sort by (`started`, `record.run_id`) ascending. Per D-02/D-03: iterate in that order; for each result with verdict `Verdict::NotExecuted` increment that run's not_executed and continue; otherwise insert into `results` keyed by test_case_id unconditionally (last write wins; no verdict ranking, no max), and if an earlier entry existed increment the earlier run's superseded count and, when the earlier run's `started` equals the current run's `started`, push the D-16 tie note. Track per-run counters in a BTreeMap keyed by run_id. After the loop, decided per run = number of entries in `results` whose run_id is that run. Per D-05: build one RunReport per run in sorted order with use_ Used if decided > 0, else Excluded with the exact reason strings. Per D-04: `builds` = build_id of every Used run. Copy problem_report_id and verification_result_ref from the winning result into SelectedResult (later phases need them). Display per the interfaces layout with two-space indents, two spaces between columns, no trailing spaces, final newline. No I/O, no clock, no randomness in this module.
  </implementation>
</feature>
