pub const MATRIX_SCHEMA: &str = "tcms/trace-matrix.schema.json";
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub enum InputKind { Matrix, Run }
#[derive(Debug, Clone, PartialEq, Eq)] pub enum InputStatus { Loaded, Skipped(String) }
#[derive(Debug, Clone)] pub struct InputEntry { pub path: PathBuf, pub kind: InputKind, pub status: InputStatus, pub run_id: Option<String> }
#[derive(Debug, Clone, Default)] pub struct Reconciliation { pub inputs: Vec<InputEntry>, pub notes: Vec<String> }
impl Reconciliation { pub fn discovered(&self) -> usize; pub fn loaded(&self) -> usize; pub fn skipped(&self) -> usize; }
impl std::fmt::Display for Reconciliation { /* layout below */ }
#[derive(Debug, Clone)] pub struct LoadedInputs { pub matrix_path: PathBuf, pub matrix: TraceMatrix, pub runs: Vec<LoadedRun>, pub reconciliation: Reconciliation }

pub fn check_unique_run_ids(runs: &[LoadedRun]) -> anyhow::Result<()>;
pub fn matrix_notes(matrix: &TraceMatrix, runs: &[LoadedRun]) -> Vec<String>;

  <behavior>
    Unit tests in load.rs `#[cfg(test)] mod tests`, using tempfile dirs and schemas root
    `concat!(env!("CARGO_MANIFEST_DIR"), "/../../schemas/")` (unit tests run with cwd at the crate):
    - valid matrix + runs dir with run.yaml (RUN-1), notes.yaml ("just: some other yaml"), other.yaml ("type: test_case\n..."), readme.txt -> Ok; discovered 5, loaded 2, skipped 3; reasons exactly "no `type` field", "type is 'test_case', not test_run", "not a YAML file"
    - runs dir with broken.yaml containing "a: [unclosed" -> Err whose text contains broken.yaml and "YAML syntax error"
    - run missing `tester` -> Err containing the run path (schema failure via load_and_validate_yaml)
    - matrix missing `links` -> Err containing the matrix path
    - matrix with type test_run -> Err containing the matrix path and "is not a trace matrix"
    - run declaring schema "tcms/trace-matrix.schema.json" -> Err containing the path and "expected tcms/test-run.schema.json"
    - two bad runs and a bad matrix -> one Err listing all three paths, header "3 report input(s) failed to load"
    - started_at "yesterday" -> Err containing the path and "RFC 3339"
    - a.yaml and b.yaml both with run_id RUN-1 -> Err containing "duplicate run_id RUN-1", a.yaml and b.yaml
    - the same run file passed as a file and via its directory -> Ok, counted once, no duplicate error
    - one run with two results for test case T1 -> Err containing the path, "T1" and "appears 2 times"
    - explicitly named run file that is notes.yaml (no type) -> Err containing the path and "is not a test run record"
    - nonexistent --runs path -> Err containing the path and "not found"
    - matrix link run_ids [RUN-1, RUN-9], only RUN-1 loaded -> Ok with note "matrix references run RUN-9, which was not loaded"
    - RUN-1 has results for T1 (in matrix) and T8, T9 (not in matrix) -> note "run RUN-1 has 2 result(s) for test cases not in the matrix: T8, T9"
    - Display of a Reconciliation with one loaded matrix, one loaded run and one skipped file equals the exact layout in the interfaces block (assert_eq on the full string)
  </behavior>
  <implementation>
    Per D-06/D-07/D-15/D-17, `load_inputs(matrix, run_paths, schemas_root)`:
    (1) Matrix: if not a file, failure "{path}: trace matrix not found". Read text and peek with `serde_yaml::from_str::<serde_yaml::Value>`; syntax error -> failure "{path}: YAML syntax error: {e}"; `type` not "trace_matrix" -> failure "{path} is not a trace matrix (type '{t}')" (missing type shown as type 'none'); `schema` not MATRIX_SCHEMA -> failure "{path}: declares schema '{s}', expected tcms/trace-matrix.schema.json"; else `load_and_validate_yaml::<TraceMatrix, _, _>(path, schemas_root)` with failures formatted "{path}: {err:#}". Record an InputEntry Matrix/Loaded on success.
    (2) Run discovery: for each run path, nonexistent -> failure "{path}: run input not found"; directory -> non-recursive `fs::read_dir`, every entry is a candidate marked from_dir=true; file -> candidate marked explicit. Dedupe candidates by `fs::canonicalize` (an explicit mark wins over a directory mark), then sort by path (RESEARCH pitfall 3).
    (3) Per candidate: a subdirectory inside a runs directory -> Skipped("directory; runs directories are not searched recursively"); extension not yml/yaml (case-insensitive) -> Skipped("not a YAML file") when from a directory, failure "{path} is not a YAML file" when explicit; YAML syntax error -> failure (both cases, D-15); not a mapping or no `type` -> Skipped("no `type` field") from a directory, failure "{path} is not a test run record (no `type` field)" when explicit; type other than "test_run" -> Skipped("type is '{t}', not test_run") from a directory, failure "{path} is not a test run record (type '{t}')" when explicit; schema not RUN_SCHEMA -> failure "{path}: declares schema '{s}', expected tcms/test-run.schema.json"; then `load_and_validate_yaml::<TestRunRecord, _, _>`, then `LoadedRun::new`, then the D-17 check: any test_case_id occurring n>1 times -> failure "{path}: test case {id} appears {n} times in run {run_id}". Successful runs get InputEntry Run/Loaded with run_id Some.
    (4) Collect every failure (do not stop at the first, RESEARCH pitfall 4); if any, bail with "{n} report input(s) failed to load:\n" followed by each failure on its own line indented two spaces.
    (5) `check_unique_run_ids(&runs)` (D-08): BTreeMap run_id -> Vec<path>; for each id with 2+ paths produce "duplicate run_id {id} in {p1} and {p2}" (join extra paths with " and "); bail with all such lines joined by newline.
    (6) `reconciliation.notes = matrix_notes(&matrix, &runs)` (D-18): first, sorted unique run_ids from all links not among loaded run ids -> "matrix references run {id}, which was not loaded"; then per run (sorted by run_id) the sorted unique result test_case_ids not in any link's test_case_ids -> "run {run_id} has {n} result(s) for test cases not in the matrix: {ids joined by ', '}". Notes are informational and never fail.
    Return LoadedInputs with runs in sorted-path order. All collections deterministic (BTreeMap/BTreeSet, sorted Vec). Do not call `testcase_reporting::legacy` anywhere in load.rs.
  </implementation>
</feature>

## Trust Boundaries

| user-supplied files -> load_inputs | Matrix and run YAML are untrusted evidence; they decide what the report claims |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Tampering | run/matrix YAML content | mitigate | Schema validation via load_and_validate_yaml before typed deserialize; fail closed and name the file (D-06) |
| T-01-05 | Tampering | `schema` field pointing to a lenient schema | mitigate | Require schema == RUN_SCHEMA / MATRIX_SCHEMA before validating; otherwise fail |
| T-01-06 | Repudiation | silently dropped inputs | mitigate | Every discovered file recorded as loaded or skipped with a reason in Reconciliation (D-07) |
| T-01-07 | Spoofing | two records claiming one run_id | mitigate | check_unique_run_ids fails naming both files; canonicalize paths first to avoid false duplicates (D-08) |
| T-01-08 | Tampering | conflicting verdicts for one test case in one run | mitigate | Duplicate test_case_id inside a run fails (D-17) |
| T-01-09 | Denial of service | huge or recursive directories | accept | Local CLI on user-chosen paths; directory scan is non-recursive |
</threat_model>
