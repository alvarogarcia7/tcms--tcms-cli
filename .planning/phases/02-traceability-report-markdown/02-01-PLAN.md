<task type="auto" tdd="true">
  <name>Task 1: Roll-up rule with table-driven tests (D-02, D-03)</name>
  <files>crates/testcase-reporting/src/rollup.rs, crates/testcase-reporting/src/lib.rs</files>
  <read_first>
    - .planning/phases/02-traceability-report-markdown/02-CONTEXT.md (D-02, D-03, D-05, D-06)
    - crates/testcase-reporting/src/lib.rs (add the module declaration here)
    - crates/testcase-reporting/src/select.rs (style of table-driven tests, derives used)
  </read_first>
  <behavior>
    Table (outcomes of the linked live cases -> status), every row is a test case in one table test:
    - [] -> NoTests
    - [NotRun] and [NotRun, NotRun] -> NotRun
    - [Pass] and [Pass, Pass, Pass] -> Verified
    - [Pass, NotRun] -> Partial
    - [Fail] and [Pass, Fail] -> Failed
    - [Fail, NotRun] and [Pass, Fail, NotRun] -> Failed (a fail is never diluted by NotRun)
    - [Error] and [Pass, Error] -> Errored
    - [Error, Fail] and [Fail, Error, Pass, NotRun] -> Errored (D-03: Errored ranks above Failed)
    - [Error, NotRun] -> Errored
    The result does not depend on the order of the input slice (test every permutation of [Pass, Fail, NotRun, Error]).
    Exhaustive property test: for every slice of length 0 to 4 over the four outcomes, `roll_up` returns Verified if and only if the slice is non-empty and all outcomes are Pass.
  </behavior>
  <action>
    Create `crates/testcase-reporting/src/rollup.rs` and add `pub mod rollup;` to lib.rs (keep the existing modules and the `input_summary` function untouched). Write the failing table test first (commit as test), then the implementation (commit as feat).

    Public items. `CaseOutcome` enum with variants Pass, Fail, Error, NotRun, deriving Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, with `label()` returning "pass", "fail", "error", "NOT RUN". `VerificationStatus` enum with variants Verified, Failed, Errored, NotRun, Partial, NoTests, same derives, a `pub const ALL: [VerificationStatus; 6]` in that declaration order, and `label()` returning exactly "VERIFIED", "FAILED", "ERRORED", "NOT RUN", "PARTIAL", "NO TESTS". `pub fn roll_up(outcomes: &[CaseOutcome]) -> VerificationStatus`.

    Rule, evaluated in this order (D-02, D-03): empty -> NoTests; any Error -> Errored; any Fail -> Failed; every outcome Pass -> Verified; no Pass at all (all NotRun) -> NotRun; otherwise (some Pass, rest NotRun) -> Partial. Put the rule as a doc comment on `roll_up` in this same order, and state that the callers pass only live (non-obsolete) cases (D-06, ROLL-03), so obsolete cases are not this function's concern. State in the doc comment that the status table and the precedence (error above fail; a fail with a missing run is FAILED, never PARTIAL) are the confirmed rule of D-02 and D-03.

    Do not read files or the clock. Do not add dependencies.
  </action>

  </verify>
