<objective>
Add two traceability report shapes as Markdown views over the existing `ReportModel`, selected by `test-executor report --kind traceability --shape a|b`. Shape A puts all verdicts on one row per requirement. Shape B lists each requirement's verdict followed by its test-case rows. The default grid output does not change.

Purpose: Closes backlog tcms-43.2 acceptance criteria #7 and #8. Decision D-02-G4 places this work in Phase 2 as plan 02-06, with schema validation carried by Phase 4.
Output: `render_shapes.rs` (new module), a `--shape` option on `report`, CLI tests, and a short section in `docs/TRACEABILITY.md`.
</objective>

<scope_notes>
- Requirement IDs: OUT-03 (byte-identical output) and OUT-04 (header, "not recorded"). No new requirement IDs are created.
- Interaction with locked decisions (reconciled, not overridden):
  - D-07 (rows grouped under a heading per source document) is kept in both shapes. Document headings and their ordering come from `ReportModel.documents`.
  - D-08 (fixed `normal_range`, `robustness`, `other` columns) applies to the default grid only. The user-specified shapes A and B define their own columns, and the grid is left unchanged.
  - D-04 (coverage in its own columns) is not shown in shapes A and B because the user's column list for those shapes does not include coverage. Coverage stays visible in the default grid.
  - D-14 (Inputs section at top, valid Markdown from line one) applies to both shapes.
- Out of scope: schema validation of the shapes (Phase 4, 04-02..04-04), AsciiDoc/JSON/YAML (Phase 4), any change to `ReportModel` semantics.
