<interfaces>
After Phase 2, `fn report` loads inputs, runs `select_results`, validates `--generated-at`, loads `--test-cases` and `--requirements-export`, then calls `build_model(&ReportInputs {..})` and `render_markdown(&model)`, and prints: the Phase 1 `input_summary`, a blank line, `Report kinds`, one line per kind (`  traceability: rendered below`, others `  <kind>: renderer not yet available`), then the traceability Markdown when selected. Selected kinds are sorted and deduplicated via `ReportKind` ordering (Traceability, Summary, Gaps, Problems). The same text goes to stdout or `--output`.
New library API (03-02 to 03-04): `testcase_reporting::view::ViewInput { model: &ReportModel, selection: &RunSelection }`; `summary::{build_summary, render_summary_markdown}`; `gaps::{build_gaps, render_gaps_markdown}`; `problems::{build_problems, render_problems_markdown}`. Each build_* takes `ViewInput` by value and each render_* takes the report by reference and returns String.
Exact output lines the CLI tests can assert: summary tables `| Run | Build | Used | pass | fail | not_executed | error | Total |` and `| Requirement | Level | Status | pass | fail | not_executed | error | Total |`; gaps headings `## Requirements with no test cases (N)`, `## Requirements missing a normal-range test (N)`, `## Requirements missing a robustness test (N)`, `## Test cases with no recorded result (N)`; problems table `| Test case | Verdict | Run | Build | Problem report | Requirements |`, the lines `Failed or errored results: N` and `Without problem report: N`, and the cell `**MISSING problem_report_id**`.
Test helpers in report_cli.rs (from Phases 1 and 2): matrix builder, run builder, test-case YAML builder, StrictDoc export writer, `report` runner. The run builder must be able to set per-result `problem_report_id` and verdicts `pass`, `fail`, `error`, `not_executed`; extend the helper if it cannot (keep its existing callers unchanged).
Environment: CARGO_HOME=$HOME/.cargo-user; OpenSSL is the system package.
</interfaces>
