  <action>
    Write the table-driven tests first (fixture plus small models built through `select_results` and `build_model`), then implement in gaps.rs.

    Public items, deriving Debug, Clone, PartialEq, Eq:
    - `GapRequirement { requirement_id: String, level: RequirementLevel, document: Option<String> }`.
    - `GapCase { test_case_id: String, requirement_ids: Vec<String> }`.
    - `GapsReport { header: Header, no_tests: Vec<GapRequirement>, missing_normal_range: Vec<GapRequirement>, missing_robustness: Vec<GapRequirement>, no_result: Vec<GapCase> }`.
    - `pub fn build_gaps(input: ViewInput) -> GapsReport`.

    Rules. `no_tests`: rows whose status is `VerificationStatus::NoTests` (D-03; the model keeps one row per matrix requirement, so a requirement with no tests is present). `missing_normal_range` / `missing_robustness`: rows whose `normal_range_covered` / `robustness_covered` flag is false; the flags come from the matrix and are read as is. A requirement with no tests therefore appears in both coverage lists as well as in `no_tests`: it lacks both, and omitting it would make the two lists look complete when they are not. Record this decision in the doc comment of `build_gaps`. `no_result`: from `view::linked_cases`, entries whose outcome is `CaseOutcome::NotRun`, mapped to GapCase. `document` is the section name of the row (None when not recorded). Sort every list as stated; flatten sections first, then sort by requirement ID so the document grouping does not change the order. Header copied from `model.header` (D-06). Test cases that no requirement links are not known to the model and so cannot be listed; say so in the module doc comment. No clock, no file access.
