  <name>Task 1: Summary model with per-run and per-requirement counts (D-02)</name>
  <files>crates/testcase-reporting/src/summary.rs</files>
  <read_first>
    - .planning/phases/03-summary-gaps-and-problem-reports/03-CONTEXT.md (D-02, D-06)

    - crates/testcase-reporting/src/model.rs (RequirementRow, Header)
  </read_first>
  <behavior>
    Table-driven over the fixture, each row an assertion on one line of the summary:
    - Run RUN-1: pass 1, fail 1, error 1, not_executed 0, total 3
    - Run RUN-2: pass 1, fail 0, error 0, not_executed 1, total 2 (T5 pass decided; T2 not_executed)
    - HLR-1: pass 1, fail 1, error 0, not_executed 0, total 2
    - LLR-2: pass 0, fail 0, error 1, not_executed 0, total 1
    - HLR-3: all zero, total 0
    - LLR-4: not_executed 1, total 1
    Superseded: a selection built from RUN-A (T1 pass, earlier) and RUN-B (T1 fail, later) gives RUN-A pass 0, fail 0, total 0 with the run still listed (its one result is superseded, not counted), RUN-B fail 1, total 1
    Excluded run: a run holding only not_executed results is listed with its exclusion reason, pass/fail/error 0, not_executed N, total N
    For every run row and every requirement row in every fixture above, `bucket_sum() == total`
    Runs are in selection order (started ascending, then run_id); requirement rows are in model order (document, requirement ID)
  </behavior>
  <action>
    Write the table-driven tests first (they go in summary.rs `tests`, using `view::test_support::fixture` plus small hand-built selections through `select::select_results` for the superseded and excluded cases), then implement.

    Public items, deriving Debug, Clone, PartialEq, Eq:
    - `RunSummaryRow { run_id: String, build_id: String, used: bool, excluded_reason: Option<String>, counts: ResultCounts }`.
    - `RequirementSummaryRow { requirement_id: String, level: RequirementLevel, status: VerificationStatus, counts: ResultCounts }`.
    - `SummaryReport { header: Header, runs: Vec<RunSummaryRow>, requirements: Vec<RequirementSummaryRow>, linked: ResultCounts }` where `linked` counts the distinct live linked test cases from `view::linked_cases`.
    - `pub fn build_summary(input: ViewInput) -> SummaryReport`.

    Per-run counts (D-02): pass, fail and error come from `selection.results` entries whose `run_id` equals the run, grouped by verdict, so only decided results are counted and a superseded result never is; `not_executed` is the `RunReport.not_executed` field; `total` is `RunReport.total - RunReport.superseded`, taken from the record size and not from the buckets, so that `bucket_sum() == total` is a real cross-check between two sources. If they ever disagree, `build_summary` must not hide it: use `debug_assert_eq!` and keep the counts as computed (the tests assert equality for all fixtures).
    Per-requirement counts: `ResultCounts::from_outcomes` over the row's case outcomes. The row's status is copied from the model, not recomputed (D-01).
    Header copied from `model.header` (D-06). Walk all document sections in order and flatten the rows; the summary does not group by document. No clock, no file access.
  </action>
